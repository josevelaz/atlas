# Encrypt provider tokens at rest

Provider OAuth access and refresh tokens are encrypted at rest using Better Auth's built-in `encryptOAuthTokens` option rather than stored as plaintext columns. Gmail refresh tokens are long-lived credentials to the user's entire mailbox, so a database leak, backup exposure, or overly broad query access must not be equivalent to mailbox compromise. Using the framework option keeps encryption transparent to application code: tokens are decrypted only when Better Auth hands them to the sync layer.

Existing development rows that hold plaintext tokens are not migrated in place. Decrypting requires knowing which rows are plaintext versus encrypted, and a mixed-format column invites subtle bugs; instead, plaintext rows are invalidated and affected accounts are forced through re-consent, which writes fresh tokens in encrypted form. The trade-off is a one-time re-authorization for early accounts and a hard dependency on the Better Auth secret: losing or rotating it incorrectly invalidates all stored tokens and forces global re-consent. We accept this because forced re-consent is a cheap, well-understood recovery path, while plaintext tokens are an unbounded liability.
