## What shipped

The first dedicated Atlas route renders the full desktop mail workspace:

- **Top bar** — logo + compass chip, `v0.1 · MVP` version chip, "Search or ask"
  (⌘K), "Compose" (C), divider, account avatar.
- **Sidebar nav** — Mail group (Screener / Inbox / Feed / Paper Trail) + Assist
  group (Tasks & Dates / Settings), AI usage card, "Replay onboarding". Only
  **Inbox** is navigable in this slice; the other destinations stay visually
  present (for inbox parity) but are inert — they do not route to incomplete
  placeholder screens.
- **Inbox list** — 9 mail rows with avatars, sender/subject/preview, priority +
  tag chips, timestamps, unread dots, selected-row yellow fill, and the AI
  "2 P1 threads need a reply today." banner.
- **Thread pane** — toolbar (Archive / Trash / Set aside / Reply later +
  prev/next), subject + chips, AI summary (electric-blue head, white body,
  EXTRACTED tasks/dates, confirm/calendar actions), message cards, reply
  actions. Defaults to `i1` (Priya — Q3 hiring plan) selected.
- **Local state** — row selection updates the pane; Set aside / Reply later are
  per-mail toggles whose active state fills the button with the yellow accent.

`/` is untouched. No React patterns/imports; no runtime imports from
`docs/prototype/**`. `routeTree.gen.ts` was regenerated by the dev server (not
hand-edited).

## Responsive (tablet / mobile) — functionality preserved

The prototype ships **no media queries** — its fixed 3-column grid overflows the
viewport at small sizes. To **preserve all visible inbox functionality** (the
acceptance bar), the app reflows under `.atlas-app` media queries:

- **≤1100px** — columns narrow to `200 / 320 / 1fr` (no overflow).
- **≤860px** — the grid collapses to a single scrollable column: top bar →
  sidebar (wrapped to a horizontal nav strip) → inbox list → selected thread.
  Every region scrolls in-flow so the sidebar nav, AI usage card, all 9 rows,
  the thread toolbar (incl. Set aside / Reply later), AI summary, extracted
  items, message cards, and reply actions remain reachable.

Screenshots captured at `1024x768`, `768x1024`, `390x844` confirm no content is
clipped off-canvas. This is an intentional, acceptance-allowed divergence from
the prototype's overflow behavior (functionality preserved over pixel-identity
at non-desktop sizes).

## Interaction model — SSR proof variants

The app has a documented pre-existing TanStack Start/Solid hydration error
(`template2 is not a function`) that disables client interactivity on **all**
routes, including `/`. Live clicks therefore cannot drive the UI. Following the
Task-2 SSR-proof pattern, the interaction model is proven via server-rendered
search-param variants instead:

| Variant | Proves | Result |
|---|---|---|
| `/atlas/inbox` | default selection | pane = "Re: Q3 hiring plan — final review" (i1) |
| `?sel=i5` | selecting another row updates the pane | pane = "Pull request #482 — auth refactor" |
| `?sel=i2` | " | pane = "Term sheet — redlines attached" |
| `?sel=i4` | " | pane = "Thanksgiving — flight question" |
| `?setAside=1` | set-aside toggles local state | Set aside button → `is-primary` / `aria-pressed="true"` |
| `?replyLater=1` | reply-later toggles local state | Reply later button → `is-primary` / `aria-pressed="true"` |
| `?setAside=1&replyLater=1` | both toggles | both toolbar buttons ON |

The underlying handlers (`selectInView`, set-aside/reply-later signal toggles)
are standard Solid signal updates and execute identically on the client once the
app-wide hydration error (out of scope for this task) is resolved.
