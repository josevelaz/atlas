## What shipped

The five-step onboarding walkthrough is now the first-run / replay entry to the
Atlas experience:

- **`/atlas`** — first-run entry. Redirects to `?step=0` (step 1) and renders the
  onboarding card. Skip / Open Atlas land on `/atlas/inbox`.
- **`/atlas/onboarding`** — replay entry, reachable from the sidebar's "Replay
  onboarding" action. Identical walkthrough on its own linkable path.
- **All five steps ported** with their visual panels:
  1. **Welcome** — two OAuth connect cards (Google = yellow tile, Microsoft =
     AI-blue tile), "Connect with OAuth" primary button.
  2. **Screener** — a sample screener card (Maya Chen, yellow avatar) with a
     green ACCEPT / red REJECT split footer.
  3. **Categories** — three coded category rows (Inbox lilac, Feed yellow,
     Paper Trail mint) with icon tiles + descriptions.
  4. **AI triage** — an electric-blue AI-summary panel (white body + extracted
     task/date rows with coded dots).
  5. **Empty inbox** — yellow icon box + "Your Inbox is empty." heading + body.
- **Header** — logo + compass chip, "Get started — N/5" mono progress, Skip
  (ghost button → `/atlas/inbox`).
- **Footer** — Back (disabled on step 1), step dots (5, active = yellow), Next /
  Open Atlas (primary, last step → `/atlas/inbox`).
- **Sidebar "Replay onboarding"** — now a `<Link>` to `/atlas/onboarding`.

`/` and `/dev/design-system` are untouched (zero onboarding-CSS leakage,
confirmed by grep). No React patterns/imports; no runtime imports from
`docs/prototype/**`. `routeTree.gen.ts` was regenerated by the dev server.

### Navigation under broken hydration

The app has a documented pre-existing TanStack Start/Solid hydration error
(`template2 is not a function`) that disables client interactivity on **all**
routes. Per the Task-2 SSR-proof pattern, the onboarding flow is therefore
**link-driven**: every control is a `<Link>` that renders a real `<a href>`
server-side, and the current step is owned by the route via the `?step=N` search
param. Every Back / Next / Skip / Open Atlas / Replay transition is observable in
server-rendered HTML and works without JS:

| Step | Back | Next / Open Atlas | Skip |
|---|---|---|---|
| 1 | _(disabled)_ | `?step=1` | `/atlas/inbox` |
| 2 | `?step=0` | `?step=2` | `/atlas/inbox` |
| 3 | `?step=1` | `?step=3` | `/atlas/inbox` |
| 4 | `?step=2` | `?step=4` | `/atlas/inbox` |
| 5 | `?step=3` | `/atlas/inbox` (Open Atlas) | `/atlas/inbox` |

Replay link (inbox sidebar) → `/atlas/onboarding?step=0`. Verified via
`curl` against server-rendered HTML (`data-action` + `href` attributes).

## Responsive (tablet / mobile)

| Viewport | Mean diff vs proto | Within 14/255 | Notes |
|---|---|---|---|
| 1024×768 | 10.98 | 93.9 % | Card centered, shadows/borders/colors match prototype. |
| 768×1024 | 10.99 | 93.9 % | Same — card uses `max-width: calc(100vw - 48px)` in both. |
| 390×844 | 46.18 | 49.3 % | **Intentional, acceptance-allowed adaptation** (below). |

At ≤1024px the prototype card and the app card both shrink via
`max-width: calc(100vw - 48px)` — parity holds (≈94%).

At **390px** the prototype has **no breakpoints** and its 720px card overflows
the viewport. To preserve all onboarding functionality (the acceptance bar), the
app adds a scoped `@media (max-width: 560px)` rule: reduced padding (18px body),
smaller title (24px), top-aligned scroll container, and stacked connect cards.
Edge detection confirms the app card renders fully in-bounds (L=12 → R=383,
12px gutters) with no clipping — every control (Back / Next / Skip / dots /
visual) remains reachable. This mirrors the Learnings note that the prototype
overflows on small screens and small-screen work may need Atlas-scoped
functional adaptations while preserving desktop parity.

## Interaction proof (SSR — server-rendered HTML)

| Control | Proven via | Result |
|---|---|---|
| **Next** | `GET /atlas?step=0` | `data-action="next"` → `href="/atlas?step=1"` |
| **Back** | `GET /atlas?step=2` | `data-action="back"` → `href="/atlas?step=1"` |
| **Back disabled** | `GET /atlas?step=0` | no `data-action="back"`; disabled `<button>` |
| **Skip** | every step | `data-action="skip"` → `href="/atlas/inbox"` |
| **Open Atlas** | `GET /atlas?step=4` | `data-action="open"` → `href="/atlas/inbox"` |
| **Replay onboarding** | `GET /atlas/inbox` | `data-action="replay-onboarding"` → `href="/atlas/onboarding"` |
| **Step content** | `GET /atlas?step=0..4` | step 1 "Welcome"/connect; 2 "Screener"/Maya/ACCEPT/REJECT; 3 "Three categories"; 4 "AI helps you triage"/AI summary; 5 "Atlas organizes new mail"/"Your Inbox is empty" |
| **Finish lands on inbox** | follow Skip/Open Atlas href | `/atlas/inbox` → HTTP 200 |

The underlying step / nav handlers are standard Solid signal-backed search-param
reads; they execute identically on the client once the app-wide hydration error
(out of scope for this task) is resolved.
